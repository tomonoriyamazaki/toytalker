# AEC入力クリップの比較修正（2026-09-12）

21:03の「とりあえず長く話してみて」へのCartesia応答は、2番目のPCMフレーム受信中に `cause=aec_level` で停止。本文の続きは届いていた。AEC用マイク変換のclips=7,043 / clip_frames=64、missing/mic_drop/ref_drop/clock_resets=0。NLPはAGGR。止まる直前の候補窓はout=1,933/1,880/1,837/1,482で、最後のフレームはref=0。音源・クリップの原因・内部残響の時間は未確定だが、AEC入力の数値上の飽和は確認できる。

## 比較変更

旧変換はraw >> 14からDCを除去し、そのままint16へ飽和させていた。符号付き32bit全域を16bitへ収める変換よりゲインが高く、マイク入力が大きいとAECへ渡す前に波形が頭打ちになる。

`AecMicHeadroom.h` でDC除去後の32bit値を4で割ってからint16へ変換。すでに飽和した波形を小さくするのではなく、飽和前の値に余裕を持たせる。AEC前後のRMSを4倍してゲートと音量ログへ戻し、固定閾値を実質的に4倍へ上げることは避ける。ただしAEC/NLP内部の動作は絶対振幅にも依存し得るため、音響的な等価性や声の感度維持を保証するものではない。

参照音、再生音量、STT用マイク変換、NLP=AGGR、割り込みRMS 1,200/128ms、クリップ後の保護256ms、即時ボタン消音は維持。入力の過大値そのものを解消したとは主張しない。参照時刻やDC除去処理も今回同時に変えない。

`[AEC_INPUT] divisor=4 gate_rms_multiplier=4` で設定確認。`pre_scale_clips` は旧ゲインなら飽和するサンプル数、`actual_clips` は今回AECへ渡す値で実際に飽和したサンプル数。従来の `[AEC_STATS] clips` もactual側。クリップ保護にはactual側を渡すので、保護に頼っていた誤停止が増える可能性もあり、実機で効果を確認する。

## 確認方法

- 同じCartesiaの声・音量・配置で無発声の長めの返答を聞く。actual_clipsの減少と誤停止の有無を確認。
- 普段の声で「ちょっと待って」と言い、声の反応が保たれるか確認。
- ボタン短押しと通常の録音復帰を確認。
- 不調なら前の `$env:TEMP/toytalker_v07_button_aggr` を書き戻す。

固定音声再生ではないため予備比較。旧ログだけから、入力ゲイン変更で必ず改善すると断定できない。

## 21:16 実機結果：途中停止は残る

「なんか適当に、昔話とかしてみて。」へのCartesia応答（再起動後turn=2）は2番目のPCM受信中にcause=aec_levelで停止。ユーザーも途中停止を報告。`pre_scale_clips=11843 actual_clips=258`。同じ入力について旧ゲインで飽和し得たサンプルの約97.8%は新変換で飽和しなくなったが、飽和は残り、誤停止対策として十分ではなかった。前回と同じ波形ではないため、前回の7,043との直接的な改善率にはしない。

候補窓出力（旧単位換算）1,812/8,132/11,684/5,680、出力/入力比27.3%。入力ピーク86,640、全体抑制4.6dB、missing/mic_drop/ref_drop/clock_resets=0。入力を縮小しても残留成分が停止条件を満たす。ここから追加のゲイン縮小や閾値上げを成功策と断定しない。実際の入力振幅・音響配置/音量・参照整列の切り分けが必要。比較版は採用確定せず、そのまま保持し追加書き込みはしていない。

## 21:37 自動割り込み停止を無効にする比較

入力縮小前へ復旧後のturn=6で、ユーザーが最後の一文の欠落を報告。「あなた様は、どのようなものがお好きですか？」のPCM 113,520 bytesを全量受信し、done=1 / http_complete=1 / failed=0。その約3.3秒後、残りの再生中にAEC_TRIGGER、cause=aec_level、interrupted=1、DMA flush未完了。履歴の全文保存は聴取完了を保証しない。

ユーザーの依頼で `AEC_BARGE_DETECT_ONLY=true` に変更。AEC計測は継続するが、その判定ではアンプ停止・再生キャンセルをしない。生マイクのフォールバックも従来どおり計測のみ。ボタン即時停止は維持。

21:38にビルド成功（Flash 1,476,382 bytes / 静的RAM 67,128 bytes）、COM12へ書き込み・ハッシュ検証済み。起動ログの `aec_detect_only=1`、Soniox接続とSTT送信fail=0を確認。聴取確認はこれから。同じログへの取得を21:38:49〜22:08:49で再開した。

入力縮小を再導入しないよう `TOYTALKER_AEC_MIC_DIVISOR` を追加し、既定値を1（縮小なし）へ戻した。4を指定すると以前の縮小実験になる。数値テストは1/4の両設定でコンパイル成功。AGGRビルドは `compiler.cpp.extra_flags=-DTOYTALKER_AEC_NLP_LEVEL=1`、保存先 `$env:TEMP/toytalker_v07_detect_only_aggr`。長めの応答の最終文までの再生と、ボタン停止を実機で比較する。
