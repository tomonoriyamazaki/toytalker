## 基板設計の覚え書き

版ごとにフォルダを残す（`devices/KiCad/toytalker_mini_v0.X/`。配布した版は消さない）。今の版は [CLAUDE.md](../CLAUDE.md) の「基板」の行。各版の `PARTS_LIST.md` が値とネットの正、`PINMAP.md` が GPIO の正で、「設計の状態」節に何を変えたか・残りを書く。

### 発注前チェック
- 寸法・配置・向きの根拠は、データシートの縮尺付き実寸図（Physical Dimensions）とファイル座標の実測にする。「not to scale」の模式図で判断しない。過去にESP32-S3-MINI-1を正方形と誤認した（実寸15.4×20.5、アンテナ含む）。
- **自作したフットプリントは JLCPCB の部品ページの Footprint と必ず突き合わせる**（下の「フットプリント・記号の作り方」）。v0.3 で SPH0655 のパッドが 0.26mm ずれていたのをこれで見つけた。
- 発注前に、3Dビューア確認、原寸紙テスト（実物部品を1:1印刷に載せる）、DRC・ERC（既知の指摘以外ゼロ）、JLCPCBのDFMとガーバービューア確認を行う。
- JLCPCB の注文条件は v0.2 と同じにする: 2層・厚さ 1mm・緑・HASL（有鉛）・1oz・ビアはレジストカバー・最小ビア穴 0.3mm/(0.4/0.45mm)・外形公差 ±0.2mm。設計の穴は v0.3 からすべて 0.3mm 以上（0.3 未満かつビア径 0.4 以下だと追加料金の対象）。

### フットプリント・記号の作り方（v0.3 で確立）
- **優先順位**: ① 前の版の基板に埋め込まれている実績のあるフットプリント（`.kicad_pcb` の `(footprint ...)` ブロックから取れる。v0.3 の SSAJ110100 はこれ）→ ② JLCPCB（EasyEDA）のフットプリント → ③ メーカーのデータシートから自作。③ のときも ② と照合する。
- **JLCPCB のフットプリントの取り方**: `https://easyeda.com/api/products/<LCSC番号>/components?version=6.4.19.5` を取ると JSON が返る。`result.packageDetail.dataStr.shape` の `PAD~形~x~y~幅~高~層~ネット~番号~穴半径~...` を読む。単位は 10mil（×0.254 で mm）、原点は `dataStr.head` の x・y。銅の形がおかしいことがある（SPH0655 の GND リングが幅 0.07mm の線になっていた）ので、**位置と大きさだけを信じて、銅の形は自分で描く**。
- **データシートの読み方の罠**: 寸法線が「パッドの中心まで」か「パッドの縁まで」かを確かめる。確かめ方は、その寸法でパッドを置いたときに本体の外形からはみ出さないか（はみ出すなら縁までの寸法）。
- **記号**: 基板に効くのはピン番号とフットプリントのパッド番号の対応だけで、絵は何でもよい。ピン番号は前の版と揃える。ON/OFF の向きなど、配線から推定した注釈は実物で確かめる。
- **配置と配線の既存部分は動かさない**。差し替える部品の原点を前の版と同じにし、配線の先端だけを新しいパッドへ付け替えると、他の部品の DRC 結果が変わらないので差分が確かめやすい。
- ファイルはすべてテキスト（S式）なのでスクリプトで書き換えられる。回路図は `(lib_symbols ...)` に記号が埋め込まれていて `libs/symbols/*.kicad_sym` と一致していないと ERC が `lib_symbol_mismatch` を出す（両方を同じ内容にする）。回路図の `(instances (project "名前" ...))` はプロジェクト名と一致させる。

### 確かめ方（kicad-cli。KiCad 10）
```
"/c/Program Files/KiCad/10.0/bin/kicad-cli.exe" sch erc -o erc.txt  toytalker_mini_v0.X.kicad_sch
"/c/Program Files/KiCad/10.0/bin/kicad-cli.exe" sch export netlist -o net.txt toytalker_mini_v0.X.kicad_sch
"/c/Program Files/KiCad/10.0/bin/kicad-cli.exe" pcb drc --refill-zones --save-board --schematic-parity --severity-all -o drc.txt toytalker_mini_v0.X.kicad_pcb
"/c/Program Files/KiCad/10.0/bin/kicad-cli.exe" pcb export svg --page-size-mode 2 --layers "F.Cu,F.Mask,F.Paste,F.SilkS,F.Fab,Edge.Cuts" -o front.svg toytalker_mini_v0.X.kicad_pcb
```
- 基板を書き換えたら DRC を `--refill-zones --save-board` 付きで回してベタを再充填し、報告は前回の報告と `diff` する（増えた指摘だけ見る）。SVG は `--page-size-mode 2` だと基板の外形が原点になり、座標は基板座標から (12, 12) を引く。
- ERC は 0 件が基準。DRC の既知の指摘（v0.3 で 19 件）: U4（MAX98357 の BGA）のマスク橋 13、J1 の銅と端 0.48mm（2）と J1 のシルクと端（2）、U3 のライブラリ不一致（1）、U1 放熱パッドのネット衝突（2）、S2/U3 のシルク重なり（1）、MK1 のマスク円と穴（1）。回路図照合は参照記号なしの穴フットプリント 9 個と U1 のパッド 12/13 が常に出る。これ以外が出たら直す。
- **製造ファイル（ガーバー zip・bom.csv・positions.csv）**は Fabrication Toolkit（KiCad のプラグイン。GUI の代わりに CLI でも出せる）で `production/` へ。v0.2・v0.3 とも自動回転補正あり・ベタ再充填ありで出した。zip は `.gitignore` の `*.zip` で git に入らないので発注前に出し直す。
```
cd "C:/Users/exodj/Documents/KiCad/10.0/3rdparty/plugins" && "/c/Program Files/KiCad/10.0/bin/python.exe" -m "com_github_bennymeg_JLC-Plugin-for-KiCad.cli" --path "<基板の .kicad_pcb の絶対パス>" -t -f -nI -nB
```
  部品番号は回路図の各部品の **`LCSC Part` 項目**から BOM に入る（v0.3 で全部品に入れた。回路図で部品を変えたらこの項目も直し、「回路図から基板を更新」で基板側にも写す）。
  出したら前の版の bom.csv・positions.csv と `diff` して、変えた部品の行だけが違うことを確かめる。
- **JLCPCB の配置プレビューで部品がずれる・向きが違う問題の根治（v0.3 で実施）**: JLCPCB は CPL の座標を「EasyEDA フットプリントの原点」、角度を「EasyEDA フットプリントの向きからの回転」と解釈する。うちの KiCad フットプリントは原点（アンカー）や 0° の向きが EasyEDA と違う部品があり、そのままだとプレビューでずれる（ピンクの丸＝JLC モデルの 1 番ピン、白い丸＝基板の 1 番ピンが合わない）。対策は部品ごとに **`FT Position Offset`（x,y。部品ローカル座標で y は上が正）と `FT Rotation Offset`（度）** を回路図の部品と基板のフットプリントに入れること。Fabrication Toolkit がこれを読んで positions.csv に反映する。v0.3 で入れた値: J1 "0,2.324"、MK1 "0,0.706"、S1 "0,0.603"、U3 "0,-2.525"、U1 回転 270、U2 回転 180、U4 回転 180。
  値の求め方は道具にしてある: `python devices/KiCad/tools/jlc_offset_check.py <基板.kicad_pcb> [REF ...]`。EasyEDA の API からその部品のパッド座標を取り、うちのパッド座標と重ね合わせて推奨値を出し、今の値と違う部品に印を付ける（同名パッドの位置で向きを決める。LED のように名前が違う部品は向きを別途確認）。**部品を足した・変えたら、LCSC Part を入れてからこれを回し、印が付いた部品の値を回路図の部品と基板のフットプリントに入れる。**
  v0.2 までは JLC のエンジニアが手で直していた（U2 は毎回向きが違い、注文画面で手直ししていた）。
- ネットの確認はネットリスト（`sch export netlist`）で、差し替えた部品のピンがどのネットに付いたかを読む。目視は SVG を PNG にして該当部分だけ切り出す（PyMuPDF）。

### 次の基板改修で行うこと

**v0.4 の変更候補（2026-11-13 に挙げたもの。迷っている項目を含む。設計に入る時にここから決める）**

- **モジュールを ESP32-S3-WROOM-1-N16R8（フラッシュ 16MB・PSRAM 8MB）へ（2026-11-14 決定。v0.4 で替える。同日にデータシートと配置を確認）**: きっかけはボイスキーホルダーモード（[ESP32ファーム](esp32-firmware.md)）と、この先に足したいモード（おでかけモード、BLE でスマホへ送る録音文字起こし、おうむ返し）。いまの MINI-1-N4R2 はフラッシュ 4MB で、OTA 用にアプリの枠を 2 つ取ると、音声の置き場は 384KB、ファームの余裕は約 278KB しか残らない。4MB の区画はもう限界まで切ってあり、切り方では増えない。16MB なら「アプリ 4MB × 2 ＋ データ約 7.9MB」に切れる（8MB だと 3MB × 2 ＋ 約 1.9MB）。
  - **型番（データシート MINI-1 v1.7・WROOM-1 v1.8、どちらも 2026-03-02 版で確認）**: MINI-1 は N8（8MB・PSRAM なし）と N4R2 の 2 種類だけで、PSRAM 付きでフラッシュを増やせる型は無い。WROOM-1 は 18.0×25.5×3.1mm（MINI-1 は 15.4×20.5×2.4mm。高さは外装の 4mm 制約に収まる）。N8R8 と N16R8 は外形・ピンが同じで、価格差もほぼ無い（JLCPCB の部品ライブラリのミラーで N16R8 $5.14・在庫 22,306、N8R8 $4.98・10,984、MINI-1-N4R2 $4.96・7,088。取得日時が分からないので発注前に見直す。どれも Extended）。後から増やせないので N16。
  - **R8 にすると変わること**: ① GPIO35・36・37 は 8 線の PSRAM につながり使えない（データシートのピン表の注記）。GPIO33・34 は WROOM-1 では外に出ていない。いまのマイク DATA（34）・ボタン（35）・アンプ WS（36）・BCLK（37）を移す ② ビルドが `PSRAM=opi` になり、リンクするライブラリが 4 線の PSRAM（v0.3 以前）と別になる（コア 3.3.11 の `boards.txt` で確認）。**.bin は基板の版ごとに 2 本**になり、OTA は版ごとに配る .bin を分ける。4MB の機器には新しいモードが全部は入らない ③ 周囲温度の上限が 65°C（PSRAM の ECC を有効にすれば 85°C、使える PSRAM は 1/16 減る）。次点は同じ外形の N16R2（4 線 2MB。いまと同じ .bin が動く見込みで、35〜37 も使える）。
  - **配置（v0.3 の基板ファイルのコートヤードに当てて計算。配線は引いていない）**: 20mm 丸型スピーカーを残すと WROOM-1 は横置きしかできず、3V3・EN・USB D± のある列が基板の上辺に張り付いて配線を出せない。**細長いスピーカー（右下に横置き）＋ WROOM-1 を縦置き（アンテナを上辺）なら収まる**。モジュール本体は x33〜51・y12〜37.5（中心 (42.0, 24.75)、回転 0）、アンテナ部は y12〜18.3。v0.3 の x<32 の部品（USB・充電・LDO・マイク・アンプ・ボタン S2）は動かさずに済み、動かすのは C6・C7・R6・C10・C11（左の列のピンの真横 x28.5〜32.3 へ）、R7（S2 の北）、BOOT ボタン S3（モジュールとスピーカーの間の帯、GPIO0 の近く）。専有面積は 698 → 864mm²（基板の 44% → 54%。コネクタ類をパッドの外形で数えた値）。ピンの案: 左の列に VBAT_ADC=4・TEMP_ADC=5・STAT1/2=6/7・MIC_CLK/DATA=15/16・BUTTON=17・USB=19/20、下の列にアンプ 4 本=9〜12・LED=13・版の抵抗=14/21/47、BOOT=0。右の列（基板の右辺側）は GPIO0 以外使わない。狭いのは ① USB D±（マイクとアンプの間 1.7mm を抜けて S2 の南を回る。D− は S2 とモジュールのパッドの間、銅どうし約 1.2mm）② モジュールとスピーカーの間の帯（高さ 4.3mm にアンプ 4 本・LED・S3・版の抵抗）。アンテナの向きが右辺から上辺に変わるので、キープアウトの置き直しと電波の強さの確認が要る。スピーカーの裏の基板の穴は開け直す。
  - **スピーカーは 22×9（2209）が前提**: 22×9 は x29.5〜51.5・y42.6〜51.6。スピーカーコネクタ SP1 は今の向きだと差し口とスピーカーの間が 2.5mm でプラグを差せないので、180° 回して差し口を北へ向ける（プラグの空間は x21.5〜25.5・y38〜44.7）。**28×9（2809）は SP1 の置き場が無い**（電池コネクタとの間が 4.1mm、USB の下は差し口が USB か電池コネクタに向く、モジュールとの間の帯は高さ不足）。はんだ付けのパッドなら載るが、量産で手はんだはしないので採らない（2026-11-14）。**28×9 を使うなら、コネクタを JST SH 横型 2 ピン（SM02B-SRSS-TB。コートヤード 5.8×6.56mm、高さ 2.95mm）に替えて USB の下へ置く**: 中心 (15.8, 39.3)・差し口を東向きで x12.5〜19.1・y36.4〜42.2。USB のコートヤード下端 y35.85 と電池コネクタのパッド上端 y43.0 の間 7.15mm に入り、差し口の前（x18.4〜26.4・y37.3〜42.5）が空く。サーミスタ TH1 は電池コネクタとスピーカーの間へ移す。アンプからの OUT± は約 11mm に伸びる。KiCad 標準フットプリントの寸法での計算で、配線は引いていない。スピーカー側に SH のプラグを付けてもらう必要がある（購入品はリード線がむき出し）。外形の面積は 20mm 丸型に対して 22×9 が約 57%、28×9 が約 75% で、音量は下がる見込み（能率が分からないので計算では詰められない）。22×9 の厚さは 4.1±0.2mm で、基板上 4mm の制約を超える（外装 v0.6.2 の寸法では蓋の裏まで 4.4mm）。どちらも購入済みで、届いたら 20mm 丸型と同じ条件（ケースなし・同じ音量・騒音計アプリ）で比べ、厚さを測る。場所の都合なので、スピーカーも v0.4 で一緒に細長い型に替える（2026-11-14 決定。下の「スピーカーを細長い型にして側面へ」の 11/13 の決定はこれで上書き）。
  - ピンを移すなら、ボタンを深いスリープから起こせるピン（GPIO0〜21）へ移すのと同時にやる（上の案の 17 は該当）。外装をこれ以上大きくできない場合の次点は、MINI のまま外付けの SPI フラッシュ（空き GPIO 4 本）で音声の置き場だけ増やす（ファームの枠は増えない）。
- **USB の位置**: 口を基板の縁に合わせるか、ケースの壁の厚さぶん外へ出すか。迷い中。考え方: USB-C のプラグは金属の先端が約 6.6mm しか無く、口が壁の奥に引っ込むほど、持ち手（樹脂）の太いケーブルが奥まで刺さらなくなる。口の面がケースの外面とほぼ同じ（引っ込みは 0.5mm 程度まで）になるよう、**壁の厚さに近いぶん基板の縁から出す**のが安全。本体側を開けて蓋側でその部分だけ足す案は、口が引っ込んだままなら同じ問題が残る。決める前に、いまのケースで手持ちのケーブル数本（持ち手の太いもの）が奥まで刺さるかを確かめる。
- **スピーカーのコネクタの位置**: ケーブルの取り回しがきついので余裕を持たせる。コネクタの前（線が出る側）に、線を曲げる空間を取る。置き場所はケースのスピーカーの位置と合わせて決める（[外装 README](../devices/enclosure/toytalker_mini/README.md)）。
- **アンプの GAIN**: MAX98357A の GAIN ピン（B2。いま未接続＝9dB）を隣の GND（C2）につなぐ（12dB）。0.4mm ピッチの BGA の真ん中の玉なので、外へ引き出して抵抗で選ぶ形（100kΩ 経由で 15dB）は標準の基板仕様では通せない。直結の 12dB だけが現実的。**効くかどうかは未確認**（いまの設定で最大の音がすでに電源の上限に当たっていれば、上げても変わらない。値は Adafruit の解説からで、データシートは未読）。基板を作る前に、GAIN ピンが出ている市販の MAX98357A 基板と同じスピーカーで 9dB と 12dB を聞き比べれば分かる。音量の経緯は [ESP32ファーム](esp32-firmware.md) の「音量」。
- **版を自動で見分ける配線**: 空き GPIO（4〜12・33。3 はストラップなので避ける）から 2〜3 本を選び、版ごとに「GND への抵抗（100kΩ 程度）を載せる・載せない」を変える。ファームは起動時に内蔵プルアップで読む（抵抗あり = 0、なし = 1）。v0.2・v0.3 にはこの配線が無く全部 1 と読めるので、**「全部 1」は v0.3 以前**に割り当て、v0.4 以降では使わない（v0.2 と v0.3 の区別は NVS の印。[v0.3 のピン割当](../devices/KiCad/toytalker_mini_v0.3/PINMAP.md)）。3 本なら v0.4 以降で 7 種類。次の版からは配線を触らず、部品表で載せる抵抗を変えるだけで版を上げられる。
- **マイクの位置**: 電池を基板の下に敷くケースでは、下向きのマイクの穴が電池でふさがり、再生音でマイクが飽和して声の割り込みが通らない（2026-11-13 の実測。[ESP32ファーム](esp32-firmware.md) の「声の割り込みはケースのマイク穴で決まる」）。**方針（2026-11-13）: マイクを基板の端（壁から 1〜2mm）へ移し、音はケースの側面のスリットから取る。** 下向きの音孔から壁まで、基板と電池の間のクッション層に溝を切って通り道にする（溝の周りのクッションが箱の中の音との仕切りを兼ねる）。電池（304040）は今のまま真下に敷ける。場所はスピーカーとアンテナから遠い隅を候補に、配置のときに決める。ケース側の寸法は [外装 README](../devices/enclosure/toytalker_mini/README.md) の「次」。
- **スピーカーを 1mm ほど内側へ寄せる（候補）**: いまはスピーカーの外周と右・手前の壁のすき間が約 0.7mm で、蓋の裏からスピーカーを囲むリブを全周 1mm 厚で立てられない。スピーカーの裏の基板の穴は残す（裏の音を基板と電池の間の層から側面のスリットへ逃がすのに使う。[外装 README](../devices/enclosure/toytalker_mini/README.md) の「これからの方針」）。
- **基板の厚さを 1.0 → 0.8mm**（ケースを薄くするため。40×40 なら反りは小さい見込み。未確認）。
- **基板の形は 40×40・片面実装のまま**（2026-11-13 に検討して決定）。電池を横に並べる 20×40 の案（電池 502040）は採らない: 部品の専有面積の合計が 675mm²（v0.3 の基板ファイルのコートヤードから集計。ESP32 334、USB-C 85、スピーカーコネクタ 41、電池コネクタ 35、スイッチ 34）で、20×40 の片面 800mm² の 84% を占め、Ø20 のスピーカーの置き場も無い（40×40 では 42%）。高さは表と裏で足し算なので、部品を裏へ回しても薄くはならない。コネクタを SH に替えても減るのは 35mm² 程度で決め手にならず、電池とスピーカーのコネクタは今のまま（少量を自分で組む間は挿すだけの方がよい）。成り立つのはケースを 40×60 程度に長くする場合だけ。
- **スピーカーを細長い型にして側面へ（2026-11-13 に出た案。未検証。**2026-11-14 に変更: v0.4 で細長い型にする**）**: 11/13 には「v0.4 は 20mm 丸型のまま、細長い型は別の版で試す」と決めたが、v0.4 でモジュールを WROOM-1 に替えると 20mm 丸型の場所が無くなるので、v0.4 で細長い型にする（上の項目）。22×9mm なら今のコネクタ（MX1.25）のまま載る。28×9mm は MX1.25 の置き場が無く、コネクタを JST SH に替えれば載る（座標と条件は上の項目）。音量が下がる心配があるので、候補はまだ探す（能率の dB、4Ω の型、面の広さを見る）。スピーカーはコネクタ接続（SP1）なので、付け替えて聞き比べられる。以下は 11/13 の記述。いまは 20mm 丸型。細長い型（2209＝22×9mm、2809＝28×9mm など。8Ω 1W）を、マイクの穴と反対側の側面に、前面を壁の穴へ密着させて付ける。ねらいは、スピーカーの音が箱の中に回ってマイクを飽和させるのを減らすこと（効くのは「離す」「密着させる」で、形は手段）。**振動する面が狭くなるので音量は下がる見込み**（音量は最優先の方針。面の広い 2030＝20×30mm も一緒に買って比べる）。うまくいけば、基板を細長くして電池の形も変えられる（基板の大きさを決めているのは ESP32 のモジュール・USB-C・電池・スピーカーの置き方）。**順番**: ① 何種類か買い、いまの基板で仮の箱に付けて、音量（耳と騒音計アプリ）とマイクの飽和（`aec_clip_frames` の割合）を比べる → ② 足りると分かってから、基板と電池の形を決める。先に基板を作り直さない。
- **ねらい**: 新しい基板を出しても、ファームは 1 本のまま全部の版へ OTA で機能を届ける。基板ごとの違い（マイク・ピン・既定の音量など）は本体が版を見て切り替える。そのために (a) 版ごとに試験機を 1 台手元に残す (b) `stable` に上げる前に全部の版で会話を確かめる (c) 古い版をいつまで支えるかを売る時に決める（ファームの容量はいま 76%）。ファーム側の作業は [ロードマップ](roadmap.md) の 27。

- 録音用 I2S の BCLK/WS を再生用と別ピンにする件は v0.2 で分離済み（録音 48/33、再生 37/36）。v0.3 は録音が PDM になり WS 自体が無くなった。
