# RTX 5090 / Qwen3-TTS 初回同時要求試験

実施日: 2026-09-12 14:22〜14:25 JST

追補: ユーザーが保存済み2件同時の音声を聴取し、問題なしと報告。その後 [4〜32件の追加測定](qwen3-tts-capacity-2026-09-12.md) を実施した。以下は初回測定時点の記録。

## 結論

短文は単独10件すべて受信成功、初回PCM p95は0.810秒。2件同時を5回実施すると10件すべて受信成功したが、初回PCM p95は2.065秒に増えた。暫定目標の1秒を超えたため、4件以上への拡大は保留した。

今回分かったのは現行APIの短文・1話者条件での遅延であり、5090の最大同時人数ではない。100人対応、長文、混在話者、継続運用、音声内容の正常性は未検証。模擬再生に枯渇はなかったが、実端末で音切れがないことの保証ではない。

## 環境と条件

- Windows / RTX 5090（32,607MiB）、ドライバー591.86。
- 稼働TTS: Python 3.13系、PyTorch 2.11.0+cu128、faster-qwen3-tts 0.2.6、FastAPI 0.136.1、Uvicorn 0.46.0。詳細版は各runの `environment.json`。
- APIソース: 1.7B Base、保存済み話者embedding、chunk_size=4、24kHz/16bit/モノラルPCM、末尾無音0.5秒。
- プロセス16796は2026-09-10 08:24:52起動。実行Pythonは確認したライブラリの配置先と一致。APIファイル更新は2026-05-09 23:19:20で、プロセス起動より前。メモリ内コードとの完全一致は未検証。
- クライアントは同じPCの専用仮想環境。標準ライブラリだけでHTTPアクセスし、別モデルのロードなし。
- localhost:8000へ要求ごとに新規接続。既存サーバーを変更・再起動せず測定。
- ケースは以下の41文字、1話者（資材の既定話者）。

> 今日は公園で何をして遊んだのかな。楽しかったことを、一つ教えてくれるとうれしいな。

- 単独10回／2件同時×5回。各runの先頭3回はウォームアップとして集計から除外。バースト間隔2秒、要求期限30秒。
- 再生推定は初期バッファ683ms。保存音声の末尾無音を除いた時間でRTFを算出。
- GPU値は約1秒間隔。デスクトップアプリ等の負荷も含み、試験以外のAPI利用が完全にゼロだったことはサーバーログで照合できていない。

## 結果

| 指標 | 単独 | 2件同時 |
|---|---:|---:|
| HTTP/PCM形式成功 | 10/10 | 10/10 |
| 初回PCM p50 | 0.768秒 | 0.804秒 |
| 初回PCM p95 | 0.810秒 | 2.065秒 |
| 要求完了時間の範囲 | 2.213〜2.704秒 | 4.713〜6.326秒 |
| RTF中央値（実時間/音声時間） | 0.327 | 0.647 |
| 模擬再生の枯渇 | 0 | 0 |
| GPU使用率のサンプル最大 | 83% | 83% |
| VRAMのサンプル最大 | 8,059MiB | 8,071MiB |

p95はnearest-rankで計算し、10件では最大値と等しい。RTFは要求待ち時間込みで、GPU推論時間そのものではない。2件の応答は同じバーストでほぼ同時に完了する例があり、単純な「1件を最後まで生成してから次」という直列処理とは断定できない。

2件同時の後、ヘルス確認を通して単独1件を追加生成。初回PCM0.904秒、完了2.298秒、形式成功・推定枯渇0。再起動なしで回復を確認した。

## 見つかった実装上の論点

インストール済みライブラリの `model.py` は共有の `talker_graph` / `predictor_graph` をストリーミング生成へ渡している。`streaming.py` は開始時に `prefill_kv` を呼び、`talker_graph.py` の同関数は共有static cacheをresetしてから書き込む。API側に生成全体を囲う排他制御はない。

このため、複数ジェネレーターが交互に進む場合には、先行要求の生成状態を後続要求が上書きする可能性がある。今回、音声破損を聴取確認したわけではないが、HTTP 200だけで並行生成が安全と判断できない。

まず保存音声を確認し、ライブラリの状態共有と実行の切り替わりを調べる。候補は、安全な直列化＋短い待ち行列での基準測定と、要求ごとの状態を分離したバッチ対応方式の比較。現在の共有モデルを単に別スレッドで呼ぶ変更は避ける。
