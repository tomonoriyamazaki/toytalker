# 原価と課金の考え方（2026-09-13 時点の方針）

従量課金で「使った分だけ、安く、気軽に」を実現するための、原価の見方と料金の組み立て。[以前のTTS単価比較](cost-estimate.md) と [月次運用レポート](ops-monthly-report.md) の前提になる。

## 1. 原価の記録と請求額の関係

```
請求額（円） = API単価（USD） × 使用量 × その月の為替 × マージン
```

- **API単価**: `toytalker-api-unit-prices` にドル建てで保存（Sakuraのみ円建て）。プロバイダー×種別ごと（`google#llm` など）。自動更新はしない。
- **為替**: `toytalker-exchange-rates` に月ごとの行。毎月1日に運用Lambdaが ECB（欧州中央銀行）の公表レートを保存し、その月は固定。行が無い月は150円で計算される。
- **マージン**: `service#margin` の1行。現在 **2.0**。これが従量課金の「売価」そのもの。
- 記録される種別は `stt / llm / tts / tool` の4つ。相槌のLLM・TTSと、AWS・為替・カード手数料は記録しない（マージンで吸収）。

## 2. 1時間の会話の原価（マージン前）

前提: 40ターン、AI発話30分、子供の発話15分、LLMはGemini 2.5 Flash（1ターン入力2,500トークン・出力80トークン）、為替152円。

| 項目 | Sakura（ずんだもん） | Cartesia（リアル系） |
|---|---|---|
| TTS | 3.6円（12,000モーラ） | 約160円（1万字超、$0.00005/字） |
| LLM | 5.8円 | 5.8円 |
| STT（Soniox） | 3.3円 | 3.3円 |
| ツール（検索2回） | 0.3円 | 0.3円 |
| **記録される原価** | **約13円** | **約170〜180円** |
| 相槌（Gemini Flash 40回＋TTS） | 1.6円 | 約2円 |
| AWS（Lambda実行が中心、転送・ログ・DynamoDB） | 3.3円 | 約4円 |
| カード海外手数料（約2%） | 0.3円 | 約4円 |
| **本当の原価** | **約18円** | **約190〜200円** |

- DynamoDBは1時間で0.1円未満。ログを何年ためても問題にならない。
- 記録外の原価は「ターン数に比例」なので、TTSが安いSakuraでは記録原価の約40%、Cartesiaでは約3%にあたる。

## 3. マージン2.0での収支

| ボイス | 請求（1時間） | 本当の原価 | 決済手数料（Stripe 3.6%） | 手元に残る割合 |
|---|---|---|---|---|
| Sakura | 約26円 | 約18円 | 約1円 | 約27% |
| Cartesia | 約350〜400円 | 約200円 | 約13円 | 約45% |

どちらも赤字にならない。**マージン2.0で進め、月次レポートで実請求と見比べて薄ければ2.5に上げる**。値はDynamoDBの1行なのですぐ変えられる。過去の記録は計算時の値を保持するので遡って変わらない。

## 4. 為替と手数料の扱い

- **為替は月初にECB値で固定**。市場レート（Googleの表示など）とは1〜2%ずれることがあるが、月単位の記録としては誤差の範囲。実勢に寄せたければ運用Lambdaを毎日更新に変えられる。
- **各社からの請求**はドル建て都度課金（OpenAI・Anthropic・Soniox・FishAudio）、前払いクレジット（Cartesia月額・Serperパック）、円建て（Sakura、Googleは請求アカウント次第）が混在する。カードで払う分には海外事務手数料（1.6〜2.2%）が乗る。
- 実支払いと記録額を一致させようとせず、**ずれはマージンで吸収し、月次レポートで確認する**。
- ユーザーから受け取る側の決済手数料（Stripe約3.6%、App Store 15〜30%）は別物で、売上から引かれる。

## 5. 従量課金の形

- **前払いポイント制**を採る。例: 500円分を購入し、会話のたびに請求額ぶんを減らす。未払いリスクが無く、少額決済の繰り返しを避けられ、ユーザーにも上限が見える。
- いまの記録（利用者・日・種別ごとの円額）がそのままポイント減算の元データになる。
- iOSアプリ内でポイントを売るとApp Store手数料がかかるため、Web購入の経路を検討する。規約・法規制は実装前に確認。
- アプリの声の選択画面に「この声は1回約9円」「ずんだもんは1回約0.7円」のように単価を出し、従量の納得感を作る。

## 6. ポケとも（シャープ）との比較

| | 1回あたり | 400回ぶん |
|---|---|---|
| ポケとも（ノーマル495円/400回、他プランも同単価、無制限3,300円） | 約1.24円 | 495円 |
| ToyTalker Sakura | 約0.65円 | 約260円 |
| ToyTalker Cartesia | 約9円 | 約3,600円 |

Sakuraならほぼ半額で、使わない月は0円。ポケともの1回1.24円は市場が受け入れている水準なので、マージンを上げる余地はある。

## 7. プレミアムボイス（声優の声など）の料金体系

- **使い放題の定額はしない**。声優クローン級の単価（1ターン原価約4.5円）だと、月730ターンで原価割れになる。子供が気に入って使い込むほど赤字になる構造は避ける。
- 採る形は「**月額固定（解放料）＋従量（今までどおり）**」。
  - 月額は声優へのライセンス料をまかなう。ライセンスが売上分配型なら月額は低めでも成立する。
  - 会話はその声の原価×2.0をポイントから消費（1回約9円）。使われ方に関係なく変動費は従量が必ずカバーする。
  - 二重取りに見えないよう、月額にポイントを少し含める（例: 月額500円に300円分のポイント込み）。
- 声優のライセンス条件（用途・期間・停止時の扱い・分配率）は料金設計より先に固める。AIによる声の合成は業界的に敏感なので契約を明確にする。
- 実装: `toytalker-voices` にプラン印を付け、アプリの出し分けに加えて**Lambda側でも加入者かを確認**してから合成する。コスト記録は声ごとの単価で計算しているので変更なし。

## 8. 今後の課題

- **単価をモデル単位にする**: 現在はプロバイダー単位（`google#llm`）。同じ会社で2つ目のモデルを使う前に、`google#llm#gemini-2.5-flash` → `google#llm` の順で探す二段構えにする。既存行のキーは変えず、モデル付きのキーで行を足す。
- **単価行の属性**: 2026-09-13に全行へ `provider` / `api_type` を属性として追加した（キーを `#` で分けた値）。コンソールでの絞り込みと集計コードの簡略化のためで、計算はこれまでどおりキーで引く。新しい行を足すときもこの2つ（モデル付きなら `model` も）を入れる。
- **Sonioxの見積もり**: 文字数から逆算しているが、実際は音声を流した時間で課金されている可能性がある。ESP32は聞いている間ずっと送るので、月次レポートの手動確認で最初に見る。
- **LLM入力トークン**: 会話履歴を長く持つほど膨らむ。履歴の上限を決めておくと原価が安定する。
- **相槌の定型音声化**: 原価よりレイテンシ改善の効果が大きい。別件として検討。
- **AWS Lambda**: 本文Lambdaは2GBでLLM・TTSの応答待ち中も課金される。記録外の原価では最大の項目。
