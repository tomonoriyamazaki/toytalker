# ToyTalker Mini 部品の役割と電源の流れ

> **このファイルの役割: 「なぜそうしたか」。** 設計判断の経緯・実測・データシート裏取りのアーカイブ。**現在の値・ネットの正は PARTS_LIST.md**(このファイル内の値は当時の記録で、更新保証なし)。

v0.1実基板のネットリストから検証済み(2026-08-12)。v0.2の変更計画も末尾に記載。

## 電源の流れ(v0.1 現状)

```
USB-C(J1)                     バッテリー(J2)
   │VBUS                          │VBAT
   │ C1 10uF                      │ C2 10uF
   └────→ U1 BQ25185 ←───────────┘
           │  充電IC+パワーパス:
           │  ・USBがあればUSBからV_SYSへ給電しつつVBATを充電
           │  ・USBがなければVBAT→V_SYSへ放電
           │V_SYS (C3 22uF)
           ▼
        S1 スライドスイッチ ← ★全システム電流が接点を通過(定格10mAに対し実力500mA級=50倍オーバー)
           │V_SYS_SW (C4 22uF)
           ▼
        U2 AP2112K (3.3V LDO, 定格600mA)
           │+3V3 (C5 22uF)
           ├──→ U3 ESP32-S3-MINI (C6 0.1uF直近)
           ├──→ MK1 マイク SPH0645 (C8 0.1uF直近)
           └──→ U4 アンプ MAX98357 (C9 10uF直近) → SP1 スピーカー
```

### 電流の制限ポイント早見表

| 場所 | 上限 | 意味 |
|---|---|---|
| 入口: BQ25185 ILIM (R3=13kΩ) | 約1.1A | USBから引き込める上限。バッテリー接続時はピーク不足分をバッテリーが補う |
| 充電: BQ25185 ISET (R4=620Ω) | 500mA | バッテリーへの充電電流 |
| 出口: AP2112K | 600mA | 3.3Vを作れる上限。ESP32(WiFiピーク~500mA)+アンプが同居=窮屈 ★v0.2検討事項 |
| S1接点 | **10mA** | ★大幅超過中 → v0.2でEN方式化 |

## ⚠️ 名前の衝突に注意: 「EN」が2つある

| | どこのEN | 役割 | v0.2での扱い |
|---|---|---|---|
| ESP_EN | **ESP32の**ENピン(R6/C7) | チップのリセット(LOWでリセット) | 現状維持。ネット名を`ESP_EN`に |
| PWR_EN | **AP2112Kの**ENピン | 3.3V電源のON/OFF指示 | ★v0.2でS1がここを制御(EN方式) |

## v0.2 電源の流れ(計画)

```
USB-C / バッテリー → U1 BQ25185 → V_SYS ──直結──→ U2 AP2112K → +3V3 → ESP32/マイク
                                    │                ↑PWR_EN
                                    │            S1(common→PWR_EN, 片側→V_SYS, 片側→GND)
                                    │            +100kΩプルダウン(保険)
                                    └──→ U4 アンプ VDD(V_SYS直結に確定 2026-08-15。LDO負荷半減)
                                          ※C9(10uF)もV_SYS側アンプ直近へ移動
                                          ※外付けプルダウン不要(SD_MODEに内部100kΩプルダウン内蔵。
                                            ESP32死亡時は自動でシャットダウン0.6µAに落ちる)
```

**アンプV_SYS直結のデータシート裏取り(2026-08-15完了、MAX98357A/B datasheet)**:
- ✅ VIH=1.3V固定(VDD非依存)→ VDD=4.2VでもESP32の3.3V信号(BCLK/LRC/DIN/SD)は正常認識
- ✅ SD_MODEは**内部100kΩプルダウン内蔵**(92〜108k保証)→ 外付けR14不要。電源OFF時(SD浮き)は自動シャットダウン
- ✅ シャットダウン電流 0.6µA typ / 2µA max → 常時通電でも発熱・電池消耗は無視できる
- ✅ 電源範囲 2.5〜5.5V(V_SYS 3.0〜4.2Vは余裕で範囲内)
- ⚠️ 最大出力(8Ω, THD10%, gain12dB): 3.7Vで0.93W → 4.2Vで約1.2W(現3.3Vは約0.75W)。**スピーカー耐入力の確認をPhase 3までに**。超える場合はソフト音量上限 or GAINピン設定で対処

v0.2追加部品: 470kΩ×2+0.1uF(電池残量分圧→GPIO1)、100kΩ×2(STAT1/2プルアップ→GPIO13/14)、100kΩ(PWR_ENプルダウン)、NTCサーミスタ×2+10kΩ+0.1uF(TH1充電保護/TH2温度可視化, C77131)、MX1.25ヘッダ(スピーカー用, HC-1.25-2PWT / C2845379)、ZHヘッダ(電池用, S2B-ZR-SM4A-TF / C265329)、サイド型スライドスイッチ(MSK12C02G15-B / C22435661)

## 部品単位の変更一覧(v0.1→v0.2)

### 変更なし(そのまま)
J1(USB-C), R1/R2(CC), C1, C2, R3(ILIM), R4(ISET), R5(TS), C3, C5, C6, R6+C7(ESP_EN ※ネット名改名のみ), D1, R7, S2, C8
※C9(アンプ用10uF)は部品同じだがネットが+3V3→V_SYSに変わるため「配線が変わる」へ移動

### 配線が変わる(部品は同じ)
| Ref | v0.1 | v0.2 |
|---|---|---|
| U1 BQ25185 | STAT1/2未接続 | STAT1→GPIO13, STAT2→GPIO14(+プルアップ) |
| U2 AP2112K | EN=VINに縛り常時ON、VIN=V_SYS_SW | **VIN=V_SYS直結、EN=S1で制御(PWR_EN)** |
| U3 ESP32 | I2S共有(3,4,5,9) | **I2S分離**: MIC=4/5/9, AMP=10/11/12。GPIO1=電池ADC, 13/14=STAT。GPIO3解放 |
| MK1 マイク | WS→GPIO3 | WS→**GPIO5** |
| U4 アンプ | BCLK=4, LRC=3, DIN=5、VDD=+3V3 | BCLK=**10**, LRC=**11**, DIN=**12**。**VDD=V_SYS直結に確定**(C9も移動。SD内部プルダウン内蔵のため外付け不要) |
| S1 スイッチ | V_SYS→V_SYS_SWの経路上 | **PWR_ENの切替**(common→PWR_EN, 両端→V_SYS/GND) |
| C4 22uF | V_SYS_SWのデカップリング | そのまま残すがネットはV_SYS(LDO入力直近)に |

## v0.3 マイク代替検討（2026-08-31、データシート裏取り済み）

背景: SPH0645LM4H-1-8のJLC在庫が残4、姉妹品-B-8は在庫0（プリオーダー$9.65〜）。KnowlesのI2S世代は事実上入手難。

| 候補 | JLC# | 価格/在庫 | 出力 | 判定 |
|---|---|---|---|---|
| SPH0655LM4H-1-8 (Knowles Cornell II) | C22376158 | $0.75 / 2,679 | **PDM**（I2Sではない） | v0.3候補①。フットプリント・ファーム両方の変更が必要 |
| ICS-43434 (TDK InvenSense) | C5656610 | $4.08 / 4,916 | I2S | v0.3候補②。ファームほぼ無変更。ピン配置互換性は未照合 |

**SPH0655の裏取り結果**（Knowles datasheet Rev C）:
- 出力は「single bit PDM output」= クロックとデータの2線式。I2SのWS（左右の合図線）が存在しない
- ピン配置: 1=DATA / 2=SELECT / 3=GND / 4=CLOCK / 5=Vdd の**5パッド**。SPH0645は6パッド（1=WS/2=SELECT/3=GND/4=BCLK/5=VDD/6=DATA）で、パッド列間隔も1.675mm vs 1.80mmと異なる → **載せ替え不可、v0.3でフットプリント変更必須**
- 外形は同一 3.5×2.65×0.98mm、底面ポート。電源1.65〜3.6V（3.3V駆動OK）
- クロック1.2〜4.8MHz（Normal）。ESP32-S3はPDMマイク受信に対応しており、既存のMIC_BCLK線→CLOCK、MIC_DATA線→DATAの2本で足り、WS線(GPIO33)が空く
- 音質はむしろ向上: SNR 66dB(A)（現行65）、AOP 132.5dB SPL（現行120）= 大音量で歪みにくい
- X-ray検査対象なのは現行と同じ（実装費条件は変わらず）

**未決定**: 安さ・在庫のSPH0655（PDM化）か、変更最小のICS-43434か。ICS-43434のピン配置がSPH0645と互換かの照合が次のタスク。

**生産状況の裏取り（2026-08-31追記）**: SPH0645系（-1/-B共）はDigiKeyで**Obsolete（生産終了・流通在庫限り）**。SPH0655LM4H-1は**Active**（DigiKey在庫1万個超）。なおKnowlesのコンシューマ向けマイク部門は2024年にSyntiant社へ売却され、現在の流通ブランド表記はSyntiant。I2S出力のMEMSマイク自体が市場でニッチ化しており（現行品はTDK ICS-434xxの$4〜5帯くらい）、安価な主流はPDM。

**PDMの対抗馬（JLCカテゴリ568件から、SNR64dB以上・在庫あり）**:
| 部品 | JLC# | 価格/在庫 | SNR | 感度 | 備考 |
|---|---|---|---|---|---|
| SPH0655LM4H-1-8 | C22376158 | $0.75 / 2,679 | 66dB | -37dBFS | 本命。ゲイン+11dB要 |
| Goertek SD18OB261-060 | C2895290 | $0.93 / 6,525 | 65dB | **-26dBFS** | 対抗。感度がSPH0645と同じでゲイン調整不要。同3.5×2.65mm 5P。Goertekはスマホマイク大手 |
| ST MP34DT06J | C503097 | $2.14 / 3,733 | 64dB | -26dBFS | 4×3mmで一回り大きい |
| Infineon IM69D130 | C536262 | $4.12 / 441 | **69dB** | -36dBFS | 高音質枠。将来の上位モデル用 |

v0.3設計時はSPH0655とSD18OB261の2枚看板でデータシート照合（フットプリントが同一なら基板1版で両対応も狙える）。

**SD18OB261-060の裏取り結果（2026-08-31、Goertek SPEC V1.0 2018.10.05、LCSC掲載PDF）**:
- 電源: **VDD 1.60〜3.6V → 3.3V駆動OK**（JLC一覧の「1.8V」はテスト条件の代表値だった）
- 出力: PDM。クロック Standard Mode **1.2〜3.5MHz** / Sleep 0〜150kHz。SPH0655(1.2〜4.8MHz)と重なる帯域→**ファーム設定は16kHz×128=2.048MHzで両者共通にできる**（×64=1.024MHzは両者とも下限1.2MHz未満で不可）
- ピン配置: **1=DATA / 2=L/R(SELECT) / 3=GND / 4=CLK / 5=VDD → SPH0655と番号・機能とも完全一致**
- パッケージ/ランドパターン: 3.50×2.65×0.98mm、AP Ø0.325、パッド0.725×0.522、列間1.675mm・行間0.822mm、リングパッドØ1.025/1.625・中心から1.513mm → **SPH0655のランドパターンと寸法一致 = フットプリント共通化可能**（ピン1の向きだけv0.3設計時に両図面の表裏基準を突き合わせて最終確認）
- 感度-26dBFS（ゲイン調整不要）、SNR 65dB、AOP 120dB SPL、周波数特性100Hz〜8kHz（16kHz STT用途では十分。SPH0655は〜10kHz超で広め）
- **結論: v0.3は共通フットプリント1個で、1軍=SPH0655($0.75/SNR66)、2軍=SD18OB261-060($0.93/ゲイン不要)のデュアルソース体制が可能**

### ネット名の整理(誤記・紛らわしさ解消)
- `GPIO27` → `GPIO0_BOOT`(実体はGPIO0だった)
- `Net-(U3-EN)` → `ESP_EN`(ESP32のリセット)
- 新設 `PWR_EN`(AP2112KのEN)
- `V_SYS_SW` → 廃止(V_SYSに統合)
